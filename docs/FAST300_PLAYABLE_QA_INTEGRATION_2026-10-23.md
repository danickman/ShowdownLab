### Proven real state leakage and targeted live bridge repair

The 8dc density CI run demonstrated an actual **cross-battle state leak** after the prior inline 120-fighter 10× battle. New 180-fighter Worker physics ran 571 real ticks, published 47 state messages and incurred 51k HP damage with no Worker errors, but the adapter remained stuck in `match_over` exposing the previous inline roster (raw 120, four alive). Root cause: `fast300-worker-bridge.deploy` called `inline.setRunning(false)` AFTER configuring a new adapter callback. This emits a *terminal snapshot from the previous battle*, and the new adapter accepts it as belonging to the new Worker battle. Subsequent real Worker snapshots get ignored while the adapter phase is no longer `battle`.

Fix: introduce a gated inline callback `forwardInline` that suppresses all outgoing inline snapshots while Worker is being started; gate it **before** inline.setRunning(false). Restore valid inline callback delivery when returning to smaller battle or when Worker startup fails. This preserves actual Worker clock, target/collision exactness, spells, speed and visual rendering. Add a simulated real playable bridge unit test with stale terminal snapshot and true 180 replacement state, plus existing direct Chromium lifecycle and 180/300 density QA. Bump bridge URL, SW release cache name and exact root/bridge SHA256 integrity pins. No preview/main/production deployment.

## Worker post-progress crash hardening — 23 October 2026

Additional pre-release safety issue: prior Fast300 bridge automatically re-deployed both original armies at 100% health even if the Worker crashed after genuine damaging combat. That silently fabricated a new match state and potentially changed winner/rewards. The safer failure model is fail-closed: after an active Worker snapshot with `tick>0` and no terminal winner, terminate the crashed Worker, retain the **last confirmed units/HP/tick** in the playable theatre, mark the battle paused, prohibit further spells/physics, and show an accessible bright recovery dialog. The player must explicitly choose **Restart round in safe mode**, at which point a fresh round starts via the existing match adapter but the Worker stays disabled for the rest of the page session; no rewards or winner are granted for the aborted round. Initial Worker import/startup failures before any positive tick still automatically enter the original inline engine.

All state callbacks after Worker retirement remain epoch-filtered, prior-120 stale snapshots continue to be suppressed, and normal healthy throughput is untouched. Dedicated exact-bridge fault tests inject a Worker failure after tick 47 and a separate before-tick failure, validate no silent full-HP rollback and explicit restart, and launch real 430×932 DPR3 Chromium with 300 live fighters, >20 authentic ticks, native Worker error injection, frozen HP/tick and user-authorized safe-mode restart. The service-worker cache identity, root SHA pin and bridge module SHA pin are atomically version-bumped; no main merge or deployment. Physical Safari, actual loss-of-device-focus, low-memory evictions and subjective raster sharpness remain manual acceptance.
